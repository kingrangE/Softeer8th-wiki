- docker compose 작성
    - `x-airflow-common` : 재사용할 설정 모음
        - `x-`로 시작하면, docker compose가 실제 서비스로 취급하지 않는다.
            - 아래 service 내의 `airflow-init`을 보면, `<<: *airflow-common` 이라고 되어있는 것을 볼 수 있다.
                - 이것이 x-airflow-common의 설정을 그대로 복사해서 넣으라는 의미
            - airflow관련은 모두 airflow-common의 공통 설정을 복사해서 이용한다.
        - 내부 항목
            - `AIRFLOW__CORE__EXECUTOR`: LocalExecutor
                - Task를 어떻게 실행할지 방식 선택 
                - LocalExecutor : 스케줄러가 Task를 자기 컴퓨터 안에서 직접 프로세스로 실행하는, 가장 단순한 방식 
                    - CeleryExecutor : 워커를 여러 대 두는 방식
            - `AIRFLOW__CORE__AUTH_MANAGER`: FabAuthManager 
                - Airflow UI 로그인/권한 관리를 누가 담당하는지 Airflow 3.x부터 명시적으로 지정해야 합니다.
            - `AIRFLOW__DATABASE__SQL_ALCHEMY_CONN`: postgresql+psycopg2://${AIRFLOW_DB_USER}:${AIRFLOW_DB_PASSWORD}@postgres/${AIRFLOW_DB_NAME} 
                - MetadataDB 접속 정보 전달, ${...} 부분은 .env 파일의 값으로 자동 치환
            - `AIRFLOW__CORE__LOAD_EXAMPLES`: false
                - Airflow가 기본 제공하는 샘플 DAG들을 UI에 안 보이게 함
            - `AIRFLOW__CORE__EXECUTION_API_SERVER_URL` / `AIRFLOW__API_AUTH__JWT_SECRET` / `JWT_ISSUER` 
                - Airflow 3 이후부터 필요
                - 3.x부터는 스케줄러가 태스크를 실행할 때 airflow-apiserver에게 Task 실행해도 되는지 실행 정보를 요청하는 방식
                    - 요청이 진짜인지 확인하는 용도가 `JWT_SECRET`
            - `AIRFLOW__SCHEDULER__ENABLE_HEALTH_CHECK` : true
                - 스케줄러가 "나 살아있음"을 알려주는 기능을 켜서, 아래 healthcheck가 동작
            - `_PIP_ADDITIONAL_REQUIREMENTS`: "mysql-connector-python requests"
                - 컨테이너가 켜질 때 설치할 의존성 패키지 목록
            - `SEOUL_API_KEY`, `TARGET_MYSQL_HOST` 등
                - 환경변수로 이용하기 위한 값
    - `volumes`: 볼륨 연결
        - 로컬에 있는 dags 폴더를 container 안에서도 알 수 있게 연결
            - local dag 폴더를 수정하면 자동으로 Container 안에서도 반영된다. (연결했으니까)
    - `user`,`depends_on` 
        - `user` :컨테이너 안에서 어떤 사용자 권한으로 실행할지 지정
        - `depends_on` : 의존 관계, 작성한 서비스가 ~ 되었을 때만 실행할 수 있게
    - `service`
        1. `postgres` : MetadataDB
            - healthcheck는 쿼리를 받을 수 있는지 `pg_isready`로 10초마다 확인 
        2. `mysql` : 결과 저장용 DB
            - `./sql:/docker-entrypoint-initdb.d` :  Container가 처음 뜰 때 실행할 파일들 작성 ( 테이블 생성 등)
        3. `airflow-init` : 초기화 작업용 Container
            - command에 작성한 내용으로 초기화한다. 
                - `airflow db migrate`
                - `airflow users create`
        4. `airflow-apiserver` : 우리가 브라우저로 접속하는 화면, Task 실행 요청을 받아주는 서버 역할
        5. `airflow-scheduler` : 등록된 DAG들을 확인하여, 지금 실행해야 할 Task가 있는지 체크하고 실행을 Trigger
        6. `airflow-dag-processor` : dags폴더에 저장한 py파일들을 주기적으로 읽어서 유효한 DAG로 파싱하는 프로세스
        7. `airflow-triggerer` : 비동기 대기를 효율적으로 처리하는 프로세스, 기본 구성

### DAG 구조 설계

1. XCom 대체
    - Task간 데이터 전달을 기본적으로 MetadataDB를 이용한 XCom으로 하게 된다.
        - 하지만, 이 메타데이터 값에 큰 값을 저장하면 속도가 느려지므로 문제가 생긴다.
        - 이를 방지하기 위해 아래와 같이 실행한다.
    - 대체 실행 방식
        1. 각 Task 결과 CSV 파일로 저장
        2. 파일 경로만 XCom으로 전달

2. DAG 구성 방식
    - DAG를 작성할 때는 Operator / Sensor / TaskFlow API 3가지 방식이 존재한다.
    - 본 과제에서는 TaskFlow API로 DAG를 작성한다.
    - TaskFlow API 작성 방법
        1. import
            ```python
            # airflow 3.x
            from airflow.sdk import dag,task 
            
            # airflow 2.x
            from ariflow decorators import dag,task
            ```
        2. dag 작성
            ```python
            @dag(
                dag_id="bike_station_period_usage",
                schedule=None,
                start_date=pendulum.datetime(2026, 1, 1, tz="UTC"),
                catchup=False,
                tags=["bike","usage"],
            )
            def bike_station_period_usage():
                pass
            ```
            - dag로 사용할 함수 위에 @dag 데코레이터를 작성한다.
            - 각 파라미터 설명
                - dag_id : 말 그대로 dag의 id
                - schedule : DAG가 실행될 주기/시점 설정
                - start_date : DAG 시작 시점
                    - schedule이 None이어도, start_date를 비워두면, 유효하지 않은 DAG로 판단한다.
                    - 수동 trigger 방식일 때도, 수동 trigger한 날짜가 start_date보다 미래여야 한다.
                - catchup : 멈춰있거나, 과거 날짜로 새로 배포되었을 때 누락된 과거 실행 주기들을 한 번에 소급 적용하여 한꺼번에 실행할지 결정
                    - 기본값 : True
                    - 우린 우리가 필요한 날짜만 구할거니까 False
                - tags : airflow UI에서 DAG를 필터링하여 찾기 위한 tag
        3. task 작성
            ```python
            @dag(schedule=None,start_date=...,...)
            def dag_function():
                @task()
                def collect():
                    return "raw 파일 경로" # XCom으로 전달할 경로
                @task()
                def transfrom(raw_path):
                    return "clean 파일 경로" # 정제된 값을 전달할 경로
                @task()
                def aggregate(clean_path):
                    return "agg 파일 경로"
                @task()
                def load(agg_path):
                    pass
                load(aggregate(transform(collect))) # 함수 호출 중첩 방식으로 task 순서 결정
            ```
            - task도 파라미터가 존재하지만 이는 아래에서 각 단계 구현하면서 작성예쩡
        4. config 파일 작성

### Collection 함수 구현
- Collector가 해야 하는 일
    1. API 요청 및 재시도
    2. 한 날짜의 전체 데이터를 모으는 함수 (pagination)

- 작성
    - url 만드는 함수
        ```python
        def _build_url(date: str, start_index: int, end_index: int) -> str:
            return (
                f"{BASE_URL}/{SEOUL_API_KEY}/json/{SERVICE_NAME}/"
                f"{start_index}/{end_index}/{date.replace('-', '')}"
            )
        ```
    - 특정 날짜 전체 데이터 모아서 반환하는 함수
        ```python
        def _fetch_page(date: str, start_index: int, end_index: int) -> dict:
        """
        한 페이지 요청 함수, 지수 백오프로 3번 재시도
        
        args:
            date : 요청할 날짜
            start_index : 요청할 시작 인덱스
            end_index : 요청할 끝 인덱스
        """
        # URL 생성
        url = _build_url(date, start_index, end_index)
        
        # 마지막 에러 정보 
        last_error = None

        # 최대 실패 횟수까지만 재시도
        for attempt in range(1, MAX_RETRIES + 1):
            try:
                response = requests.get(url, timeout=REQUEST_TIMEOUT)
            except (requests.exceptions.Timeout, requests.exceptions.ConnectionError) as exc: 
                #네트워크 오류에 해당하는 경우
                last_error = exc
                print(
                    f"[collect] {date} {start_index}-{end_index} "
                    f"시도 {attempt}/{MAX_RETRIES} 네트워크 오류: {exc}"
                )
                time.sleep(2 ** (attempt - 1))
                continue

            if response.status_code in RETRYABLE_STATUS_CODES:
                # 5xx 코드인 경우
                last_error = requests.exceptions.HTTPError(
                    f"{response.status_code} server error"
                )
                print(
                    f"[collect] {date} {start_index}-{end_index} "
                    f"시도 {attempt}/{MAX_RETRIES} 서버 오류: {response.status_code}"
                )
                time.sleep(2 ** (attempt - 1))
                continue

            # 4xx 에러인 경우 자동 raise (5xx는 위에서 먼저 처리)
            response.raise_for_status()

            body = response.json()
            result = body[RESPONSE_KEY]["RESULT"]
            if result["CODE"] != SUCCESS_CODE:
                raise RuntimeError(f"API error {result['CODE']}: {result['MESSAGE']}")

            return body

        raise RuntimeError(
            f"{MAX_RETRIES}번 재시도 후 실패: {url}"
        ) from last_error
        ```
    - 특정 날짜의 특정 인덱스 범위로 요청 및 재시도하는 함수
        ```python
        def _fetch_all_rows_for_date(date: str) -> list:
        """
        지정한 날짜의 전체 row를 페이지네이션으로 모아서 반환
        args:
            date : 특정 날짜
        """
        rows: list = [] # 전체 row 담을 리스트
        start_index = 1 # 시작 인덱스
        end_index = PAGE_SIZE # 끝 인덱스 (1000개씩 수집함)
        total_count = None 

        while total_count is None or len(rows) < total_count:
            body = _fetch_page(date, start_index, end_index)
            payload = body[RESPONSE_KEY] 

            if total_count is None: 
                # 총 개수 파악
                total_count = int(payload["list_total_count"])

            page_rows = payload.get("row", [])
            if not page_rows:
                # page_row가 없으면 total_count 만족 못해도 탈출
                break

        print(f"[collect] {date}: {len(rows)}/{total_count} 건 수집 완료")
        ```

### Cleaner 함수 구현
- Extract 과정에서 가져온 데이터를 정제하는 함수다. 이 함수는 아래처럼 진행되어야 한다.
    1. XCom으로 전달받은 경로의 데이터를 읽음
    2. 각 raw를 정제
    3. 정제된 결과를 저장 후, 경로 전달

- 아래처럼 두 함수로 나눠서 전체 프로세스 관장하는 메인 함수와 각 raw 정제하는 함수로 분리했다.
    1. 전체 프로세스 관장
        ```python
        def clean_rows(raw_path: str) -> str:
            """
            XCom으로 전달받은 raw_path 읽어 각 row 정제 후, CLEAN_PATH에 저장 -> 경로 반환
            """
            with open(raw_path, "r", encoding="utf-8") as f:
                raw_rows = json.load(f)

            cleaned_rows = []
            excluded_counts: dict = {}

            # 각 줄 단위로 정제 진행
            for row in raw_rows:
                cleaned, reason = _validate_row(row)
                if cleaned is not None:
                    cleaned_rows.append(cleaned)
                else:
                    excluded_counts[reason] = excluded_counts.get(reason, 0) + 1

            # 문제 생긴거 개수 정리 후 로깅
            total_excluded = sum(excluded_counts.values())
            if total_excluded:
                logger.warning("정제 중 %d건 제외 (사유별: %s)", total_excluded, excluded_counts)
            else:
                logger.info("정제 중 제외된 row 없음")

            # 결과 저장
            with open(CLEAN_PATH, "w", encoding="utf-8") as f:
                json.dump(cleaned_rows, f, ensure_ascii=False)

            logger.info(
                "정제 완료: %d건 유지, %d건 제외, 저장 위치=%s",
                len(cleaned_rows),
                total_excluded,
                CLEAN_PATH,
            )
            return CLEAN_PATH
        ```
    2. row 하나 검사하여 정제
        ```python
        def _validate_row(row: dict) -> tuple[dict | None, str | None]:
            """
            row 하나 검사 후, 결과 반환
            args: 
                row: 결과 한 줄
            return:
                dict : (cleaned_row, None) or (None, 제외 사유)
            """
            # 필요한 field 확인, 없는 값이 있으면 None
            for field in REQUIRED_FIELDS:
                if row.get(field) in (None, ""):
                    return None, "missing_required_field"

            # 필요한 field가 모두 있다면, dictionary로 변경 후, 타입 캐스팅
            cleaned = dict(row)
            for field in NUMERIC_FIELDS:
                caster = _NUMERIC_CASTERS.get(field, float)
                try:
                    cleaned[field] = caster(row[field])
                except (TypeError, ValueError):
                    return None, "numeric_conversion_failed"

            # 음수는 제외처리
            for field in NUMERIC_FIELDS:
                if cleaned[field] < 0:
                    return None, "negative_value"

            return cleaned, None
        ```

### Aggregator 함수 구현
- 집계를 위해 계산하는 함수다. 
    - 대여소 별로 묶어서 계산해야 하므로 setdefault를 사용한다.
        - setdefault : key값이 존재하면 값을 가져오고 없으면, 설정한 기본값으로 생성하는 것
- 코드
    ```python
    def aggregate_rows(clean_path: str) -> str:
        """
        XCom으로 전달받은 CLEANED_DATA로 다음 진행
        대여소 기준 GROUPBY -> 연산 -> 저장 -> 경로 반환
        """
        with open(clean_path, "r", encoding="utf-8") as f:
            rows = json.load(f)

        stations: dict = {}
        for row in rows:
            station_id = row["RENT_ID"]
            # 기본값 설정
            station = stations.setdefault(
                station_id,
                {
                    "period_start": PERIOD_START,
                    "period_end": PERIOD_END,
                    "station_id": station_id,
                    "station_name": row["RENT_NM"],
                    "total_usage_count": 0,
                    "total_distance_m": 0.0,
                    "total_duration_min": 0.0,
                },
            )
            station["total_usage_count"] += row["USE_CNT"]
            station["total_distance_m"] += row["MOVE_METER"]
            station["total_duration_min"] += row["MOVE_TIME"]

        aggregated_rows = list(stations.values())
        # 결과 저장
        with open(AGG_PATH, "w", encoding="utf-8") as f:
            json.dump(aggregated_rows, f, indent=4, ensure_ascii=False)

        return AGG_PATH
    ```
